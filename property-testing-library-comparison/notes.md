# Property-testing library comparison: working notes

A working log. Each step appends a dated entry: what was tried, what was learned.

## 2026-11-15 — Rust harness set up, catalogue fixed before any run

Built two isolated cargo packages, `rust/hegel` (Hegel, `hegeltest` 0.52.6) and `rust/proptest` (proptest 1.12.0). Each depends only on its own library plus the same three target crates by path (`cv-text`, `crucible-keys`, `crucible-layout`, cloned at the pinned commits into a git-ignored `var/` directory and never edited), edition 2024, default dev profile, so a clean build of one does not compile the other library. Each package exposes the same five properties (`url_never_panics`, `url_idempotent`, `url_invariants`, `action_roundtrip`, `action_layout_name`) written in that library's idiomatic generators, a `tests/` suite that is green on the unmutated targets (three properties at 1,000 cases plus two deterministic known-counterexample regressions for the two real defects), and an `examples/run.rs` that performs one seeded run and prints one JSON row. The run is an example rather than a `[[bin]]` so the repository's `--help` gate, which builds and probes every cargo binary, does not need the target clones.

Before the catalogue was written I ran only `cargo test` and three smoke invocations of the Hegel runner (seed 3: `action_layout_name` failed at test case 1 with `SetLayout("")`; `url_idempotent` and `url_invariants` passed). Those smoke outputs were not saved and are not result rows.

Catalogue `catalogue/rust.md` (two real defects, five one-line mutants, each with its hand-derived minimal counterexample and size measure) was written at 2026-11-15 21:16:13 -06:00 (file modification time recorded by the host; 03:16 UTC on 16 November). No result row predates it. The protocol is fixed: 50 runs per (library, defect), seeds 0-49, 1,000 test cases per run; default budgets (Hegel 100, proptest 256) are recorded in the catalogue and not used.

Hand-derived minimal counterexamples were then checked directly against the targets (not through either library, with each mutant applied and reverted): `http:arxiv.org/abs/a.pdf/` is non-idempotent, `http:a?rEf` and `http:a?gclid` leave a tracking parameter, `CycleStack(2147483648)` fails to round-trip while `CycleStack(2147483647)` and `CycleStack(-2147483648)` pass, `Kelvin(6500)` and `Slot(9)` fail while their neighbours pass. All seven catalogue entries held as written; none was amended.

## 2026-11-15 — Rust comparison runs and cost

Ran `bun rust/drive.mjs run`: 7 defects x 2 libraries x 50 seeds (0-49) x 1,000 test cases = 700 runs, rows in `results/rust/runs.jsonl` (one JSON row per run: defect, library, property, seed, status, detected, cases to first failure, the final shrunk counterexample verbatim, shrink wall time, total wall time). Every run was a fresh child process; no run errored. The mutant was applied to a throwaway clone before each defect's runs and reverted after (clones verified clean at the end). Detection table and size columns: `results/rust/detection-table.md` (`bun rust/drive.mjs summary`).

Detection k/50: both libraries 50/50 on all five mutants and on `action-layout-name`; on `url-idempotent-arxiv` Hegel 3/50, proptest 0/50. Shrink quality (exactly the catalogue minimum): `action-layout-name` Hegel 50/50 (`SetLayout("")`), proptest 27/50 (the rest `SetLayout("\t")`, size 1); `action-delta-i32` Hegel 50/50 (`2147483648`), proptest 22/50 (the rest negative, `-2147483649`); `action-kelvin-max-exclusive` and `action-slot-nine-rejected` both 50/50 on both libraries; the two URL mutants 0/50 on both libraries because the hand minimum needs a host neither generator can produce (both libraries shrink to the same list-host form, median 29 and 24 characters). Cases to first failure are test-function invocations counted by the harness (neither library exposes it directly); Hegel's first invocation is a minimal-choices case, so `action-layout-name` fails at invocation 1 in every Hegel run.

Two things worth keeping straight. First, the pre-registered minimum for `url-idempotent-arxiv` (25 characters) was wrong; the true minimum is 21 (`http:arxiv.org/pdf/a/`), found only after the Hegel runs reported 23-character counterexamples. The catalogue was left as written and an errata section records the correction; the summary reports "exactly minimal" against both values (0 of 3 against either). Second, the arXiv defect has a 1,000-case detection of 3/50 for Hegel and 0/50 for proptest, consistent with the guide's pilot (the defect needs a conjunction of three structured features); with so few detections the two libraries' rates are not separated beyond their intervals (0.013-0.165 and 0.000-0.071), so no claim is made about which finds it more often.

Cost, all *indicative* (not the standard protocol; `scripts/measure.mjs`, one build layout, no host tuning, a desktop-class 12-core CPU with the powersave governor and boost on, host type only):

- First build (`cargo test --no-run` after deleting the package's `target/`, crate registry cache warm, debug profile, 5 timed invocations after 1 warm-up): Hegel median 10.1 s (95% CI 9.77-10.16), proptest median 3.6 s (3.55-3.63). Both include compiling the three target crates and their dependencies; Hegel also builds its nested engine. That is a separation of about 2.8x, with a narrow within-run spread, labelled indicative; the first-build figure moves with the host and the cache state and is not a precise ratio.
- Warm run of one seeded 1,000-case run (the built example, 15 timed invocations after 3 warm-up, debug profile): `url_invariants` Hegel 27 ms vs proptest 97 ms; `action_roundtrip` Hegel 8.6 ms vs proptest 110 ms; the failing `action_layout_name` (including shrinking) Hegel 10.7 ms vs proptest 3.7 ms (proptest stops at the first case in the 29th invocation and shrinks almost instantly). The first two are 3.6x and 13x in Hegel's favour, the third 2.9x in proptest's; all indicative, no claim about causes. Note the debug build, generator cost and case distribution differ between the libraries, so these are not like-for-like throughput figures.

Setup used: rustc 1.99.1, cargo 1.99.1, bun 1.4.4 (drivers only), `hegeltest` =0.52.6, `proptest` =1.12.0, no system packages beyond the host's C toolchain (Hegel builds a nested engine from source). Raw measure outputs are in `results/rust/cost/` (the host name in `env.json` is replaced by `host-redacted`).

Deviations: the seeded runner is a cargo example (not a `[[bin]]`) so the repository's `--help` gate does not need the git-ignored target clones; `rust/drive.mjs` is the entrypoint and answers `--help` / `--build` / `--version`. The two packages' `target/` directories are deleted before hand-back so the private-token grep over the folder is clean (build output embeds absolute paths); rebuild with `cargo test --no-run` in each package.

## TypeScript harness log (folded in from the TypeScript worker's own log)

### 2026-11-16 (UTC)

- 03:15Z: catalogue `catalogue/ts.md` written with six mutants, hand-derived minimal counterexamples and size measures, before any comparison run. Brute-force confirmation of the minimal sets (`ts/verify-minimal.mjs`, small domain, no library) preceded it and corrected one omission (second ordering of a pair for M2 and M5).
- Harness: two packages with one library each (`ts/hegel`: `@hegeldev/hegel` 0.5.7; `ts/fastcheck`: `fast-check` 4.10.2), lockfiles committed, bun 1.4.4. The oracles (`ts/checks.mjs`) are shared, the generators are each library's own idiom (`props.mjs` in each package). Each run clones the inputs for the oracle and reports the original ones (the percentile mutant M2 sorts its argument in place).
- Design choice: each defect has one designated property (catalogue column); a "run" is one library, one defect, one seed, 1,000 test cases of that property. 50 seeds (0-49) per (library, defect) in one process per pair; Hegel run with `database` disabled in every run and in `hegel.toml`, fast-check has no persistence by default.
- Cases to first failure: Hegel is instrumented (number of body calls up to the first throwing call); fast-check reports `numRuns` (the failing run included). Shrink time = end of run minus first failure (indicative, in-process).
- Baseline: `bun test` in each package green with no mutant (7 properties at 200 cases, seed 0); `ts/defects.test.mjs` and `ts/guards.test.mjs` cover the pure decision logic and the pilot's guard examples. There are no real TypeScript defects, so no known-counterexample regression tests are needed.
- Results (`results/ts/*.jsonl`, `results/ts/tally.md`): every defect was detected in 50/50 runs by fast-check; Hegel detected all but one of 50 for M5 (49/50). The designed "hard" defect M5 was not hard for either library (both bias float draws toward the interval boundary). Shrinking differed: Hegel's finals were exactly minimal in nearly all detecting runs; fast-check's `double` shrinks left tiny denormals (for example `-5e-324`) in M2 and M5 (0/50 exactly minimal), and 37/50 exactly minimal for M3.
- Hegel's first generated case is often the simplest value, so median cases to first failure is 1 for M1, M3, M4, M6; this is a property of the library's generation order, not of the protocol.
- Cost (indicative; 10 invocations after 3 discarded rounds, no layout builds, host shared with other work, loadavg about 4, `scripts/measure.mjs`, `results/ts/cost/`): install with a warm package cache, node_modules deleted first: Hegel 3.5 ms, fast-check 2.9 ms (both far below process-start noise; no build step exists for either). Cold package cache, one run each, indicative: Hegel 0.70 s, fast-check 0.06 s wall. First property run after a clean install: Hegel about 51 ms, fast-check about 29 ms. Warm run per property at 1,000 cases, whole process: the three `clopperPearson` properties dominate (Hegel 5.3 s, 12.6 s, 11.1 s; fast-check 7.1 s, 15.7 s, 14.0 s for cp-bounds, cp-symmetry, cp-narrowing) and are cost of the target code times the generated `n`, not library overhead; the cheap properties (nd-props, pct-*) took 42-63 ms on Hegel and 22-30 ms on fast-check. No A/A floor was run, so no claim is made on separations; the nd/pct separation (about 2x) is not claimed as a finding, and the cp separation is 1.3x.
- Note on Hegel: a blocked postinstall (`bun pm untrusted`) is reported by `bun install`; the library ran regardless (as in the pilot). Hegel prints the shrunk draws and a replay blob on stderr on failure; the driver discards stderr.
- Default case budgets: Hegel 100, fast-check 100 (not run).

## 2026-11-15 — Comparison written, orchestrator re-runs

Turned `results/rust/` and `results/ts/` into `README.md` without any new comparison run or re-tuning: every number is read from `results/rust/detection-table.md`, `results/ts/tally.md`, the four cost reports, or `results/summary.md`. The last is new and comes from `analysis/summarize.mjs`, which computes the two things no existing table carried: the Rust median cases to first failure per (defect, library) from `results/rust/runs.jsonl`, and the generator line counts (non-blank, non-comment lines of the generator definitions; Rust by function, TypeScript as shared definitions plus one entry per property). Counts: Rust Hegel 103, Rust proptest 106, TypeScript Hegel 24, TypeScript fast-check 15.

The report's findings: detection saturated at this budget (Rust 50/50 on six of seven defects for both libraries, `url-idempotent-arxiv` Hegel 3/50 against proptest 0/50 with overlapping intervals; TypeScript 50/50 everywhere except Hegel M5 at 49/50), and shrinking separated the libraries (Hegel exactly minimal on `action-layout-name` and `action-delta-i32` at 50/50 against proptest's 27/50 and 22/50; fast-check's denormal floats leave M2 and M5 at 0/50 exactly minimal and M3 at 37/50). Both Rust URL mutants are 0/50 on both libraries because the hand minimum needs a one-letter host neither generator produces; reported as a generator limit. The pre-registered arXiv minimum (25) was wrong (true 21); both are reported and the catalogue is unchanged. The failure excerpts in the README are the harness-formatted details stored in the result rows; the libraries' native console reports were not saved.

Orchestrator re-runs (method evidence, run at review, no tuning): Rust `action-delta-i32`, seeds 0-49, both libraries, matched all 100 recorded rows. TypeScript `M5-pct-overshoot`, seeds 0-49, both libraries, matched all 100 recorded rows. TypeScript seed 37 run in a fresh process matched its recorded row, so the 50-seeds-in-one-process layout does not change the result.

The TypeScript worker's log (above) was folded in and its separate file removed; the one reference to it in `catalogue/ts.md` now points at this file.

Observation kept for the reader: the TypeScript warm-run `process_ms` separation for the cheap properties is about 2x, while the in-process `run_ms` separation is larger (for example 26.9 ms against 6.8 ms for `nd-props`); no A/A floor was run, so neither is claimed.

## 2026-11-15 — Closing entry

Investigation complete. Verdict: at 1,000 cases and 50 seeds the libraries are indistinguishable on detection and separate on shrinking, in Hegel's favour on both languages (proptest 27/50 and 22/50 against Hegel 50/50 on two Rust defects; fast-check's denormals on three TypeScript mutants). Cost is mixed and all indicative: Hegel's first Rust build is about 2.8x proptest's (10.1 s against 3.6 s); Hegel's TypeScript install and first run sit at the noise floor against fast-check's with a warm cache. The main validity threat is generator parity, shown directly by M5. Deferred, not done here: native console failure reports side by side, a larger or different-shaped target set (stateful, byte parsers), and a standard-protocol timing run if a cost separation ever has to be claimed.
